## Archive Class deliberately deferred

Do not implement the requested Archive Class rename, backup/export modal or permanent purge as part of this release. The user explicitly deferred it and asked about current-data impact first. No roster/delete-class code or CSV export was changed.

The current `/delete-class` route only sets `classes.deleted=1` and records an audit entry. It hides the class; it does not erase all its D1 or R2 records. The proposed actual erasure is therefore a separate change, not a rename of equivalent behavior. CSV cannot contain tabs: two tabs require an Excel workbook, or two separate CSV files. The proposed backup should contain numerical assignment/project/activity grades and historical assessment details; the wider Assessment feature revision was deferred by the user.

A future implementation can leave existing records untouched during installation, opening Archive and exporting a backup, with destructive writes reachable only after the explicit Delete confirmation. It should add no automatic purge, backfill or startup migration. Before enabling it, test class isolation, shared multi-class assignments, historical assessment records, media references, export completeness and failed/cancelled actions using fictional data. Building such a feature need not alter current student data, but a zero-risk guarantee would be dishonest. There is no new permanent-purge path in v10. Preserve the existing records until that separate update is specifically requested.
