The four-tier YY configuration and outfit interface are unchanged. New outfit artwork is separate local-only work, not an online feature in this release.

1. Comic-Con own work/gallery/peer polling changes from two seconds to a fixed ten seconds. No adaptive faster schedule is introduced. One mounted-view hub per API/assignment coordinates the timer; concurrent same-assignment probes share one in-flight request. Existing revision checks and alive/mutation protections remain. Own edits/publication/manual refresh and focus/return actions retain immediate refresh behavior. A change made by someone else can appear up to ten seconds later during regular use.
2. Active, live, non-preview assessment status checks change from five to ten seconds. Hidden views skip status checks; focus/return checks immediately. Remote pause/resume can take up to ten seconds to appear. The local one-second elapsed clock, 700 ms editing save, 30-second recovery heartbeat, final save, server enforcement, scoring and answer checking remain.
3. Teacher header and Notifications view share one teacher-owned sixty-second feed. Header alone requests authenticated GET /api/notifications-status and receives only {unread:boolean}. When the Notifications view is open, one full list supplies both the page and header each interval; this deliberately preserves current full-view freshness without introducing a fragile revision scheme. Thus the implemented change is shared polling plus lighter header reads, not incremental message storage. Local sends/seen/resolutions refresh immediately; mutation epochs prevent stale rows or obsolete failures from replacing newer state. Hidden checks pause, returning refreshes, and owner/unmount cleanup drops private cached rows. V22's one-visible-second seen acknowledgement and reply-before-resolution contracts remain.
4. Student login makes one visible recovery-cookie status discovery so pending recovery can survive reload. A failed discovery retries on focus. Only pending recovery runs a five-second interval; hidden views skip and return checks immediately. Approved/terminal states stop the timer. An expired approved reset submission rechecks status to restore reset controls, without reinstating idle polling. This compatibility discovery is one read per mounted login, not a recurring ordinary-login loop.
5. YY skips an extra account reread when authentication already loaded a current monthly marker. Monthly rollover still uses the existing conditional update. GET /yy reads persisted earned tiers first, skips history scans in redeem mode/fully earned/current-balance-covers-missing cases, inserts only genuinely missing eligible tiers in one D1 batch, then rereads persisted notice state. Where partial/historical recovery needs history it still reads current history, including after teacher threshold edits. Deluxe configuration also avoids redundant already-earned recovery. Existing point-award transactions, receipts, balances, owned items, notices, monthly policy, spending behavior, and once-only protection remain. There is no cross-request student cache or migration.
6. Teacher bank/catalog serialization is cached by the exact immutable server-owned object in an isolate-local WeakMap. Authentication and teacher role checks run before cache access; each request gets its own Response with unchanged JSON/headers and no-store. Banks/checkers/questions and historical revisions are unchanged. A catalog-first frontend conversion/client private-bank cache was deliberately not shipped: existing editors synchronously consume full problems, and an unsafe partial conversion would break them. This release implements compatible server preparation reuse only.

## When checks run

Publishing an assignment does not start a server timer for every assignment. These browser timers run only while their respective views are mounted. Leaving a view clears its timers/listeners; closing the tab ends them. A week-old comic left open can still refresh; age alone is not a stop rule. Hidden views now skip the changed polling. Dashboard, student mailbox, teacher Comic progress, Project 2 report and native Grades retain their separate existing view-scoped refresh behavior. This release does not prevent students opening existing work under its existing access/release/deadline rules.

## CPU arithmetic and limits

For one regular Comic probe loop, two to ten seconds is 30 to 6 checks/minute: 80% fewer. Coalescing previously duplicate views can reduce more, but actions/focus/real changes add requests. Assessment five to ten seconds is twelve to six checks/minute: 50% fewer. Two teacher notification loops at thirty seconds become one at sixty seconds: 75% fewer regular checks when both were mounted, or 50% fewer for the header alone. Header replies are also smaller. Ordinary login no longer repeats recovery checks every three seconds; one compatibility discovery remains, and pending recovery three to five seconds is 40% fewer periodic checks.

These percentages are request arithmetic, not a measured reduction in total account CPU or charges. One fictional warm fully-earned YY request used five SQL statements instead of eleven with identical output; database waiting is not Worker CPU. Incomplete accounts retain some scans intentionally. Bank serialization reuse consumes additional bounded warm-isolate memory. Measure representative request counts/CPU after release before claiming savings or starting deferred optimizations.
