## Teacher draft saving supersedes the old v11 Project 1 autosave rule

Project 1 teacher setup, both new and existing draft setup, keeps edits in memory until **Save Draft** or the final explicit Publish action. Merely opening the introduction, clicking Next, choosing a class, changing a title, hiding a tab, coming online, leaving or unmounting must not create/update a server draft. The initial status is Not saved, followed by Unsaved changes and Saved only after success. Restore the explicit Save Draft button in this creator.

The shared `Ev` lifecycle has a scoped manual mode. It does not write browser recovery state or silently import an old automatic recovery into manual setup. It suppresses timer, hidden-tab, online, unmount and leave-time saves. Explicit saves serialize snapshots captured at each click; later keystrokes remain unsaved rather than being silently absorbed by an in-flight save. Failed saves remain unsaved and do not silently retry while leaving. Final publication explicitly saves, activates, then releases the warning.

This restriction concerns teacher project setup. Student work still saves automatically. Other Comic-Con creators, student comic work and the published Project 1 pool editor retain their existing autosave semantics. Do not disable the generic hook globally.
